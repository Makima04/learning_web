# 数学逐题解析：提示词与输出协议 v1

已实现数学逐题解析页面与服务端异步任务；408 仍使用独立的原有解析流程。

## 使用项目当前配置的 LLM

正式调用沿用 `AppState::llm_config()` 取得运行时 URL、密钥；模型通过 `llm::active_model(&state.pool, &state.config.llm_model)` 取得，不能只读根目录 `ew_llm.json`，否则会绕过管理员在网页中更新的配置。
由 Rust 后端发起调用，前端只提交题目 ID、读取任务状态和结构化结果。数学调用使用支持题图与返回模型元数据的 `llm::chat_reply`，同样采用 temperature=0；数学提示词单独存放，不套用 `routes/kg.rs` 的 408 提示词。

提示词：[先解题与核对](../backend/prompts/math_solution.v1.system.txt)、[再组织教学输出](../backend/prompts/math_explanation.v1.system.txt)；输出协议：[JSON Schema](../backend/prompts/math_explanation.v1.schema.json)；试题输入：[本次例题](../backend/prompts/math_explanation.v1.user.example.json)。

## 一次生成任务，两阶段处理，按层阅读

先用短提示词求解并从原始条件核对，再把解题稿与原题送入教学组织提示词。两个阶段都使用项目当前配置的模型，生成任务开始时固定配置模型名和提示词版本，并记录每次网关返回的实际模型名；配置的别名背后仍可能由网关调整具体模型版本。
第一阶段返回未解出或需补充题面时，不进入正常教学解析；第二阶段仍需核对原题与解题稿是否一致，不能把先行稿当作无需检查的标准答案。
每次正常生成调用两个阶段。结构不合格时不落可用结果，用户可在冷却后重试；任务中断由租约恢复，最多尝试三次。模型生成稿不自动标记为“已校对”。

| 输出字段 | 页面展示 | 内容职责 |
| --- | --- | --- |
| problem_readback | 原题区／题目核对 | 全部必要条件与待求对象；核对符号是否读对 |
| breakthroughs | 默认显示 | 1–3 个「具体线索 → 方法 → 依据」，关联步骤 |
| steps[].title / brief | 默认显示 | 每步做什么、得到什么，独立组成完整主线 |
| steps[].details / pitfalls | 对应步骤下展开 | 可复核的演算、关键技巧和本步易错点 |
| final_answer | 独立折叠 | 完整答案及必要限制，不混入提示卡 |
| checks | 结果区展开 | 代回、边界、归一化等实际核对证据 |
| transfer | 收尾总结 | 一条可迁移经验，以及成立条件 |

展开细节不再调 LLM。切换阅读层次只是同一份结果的展示状态。
长内容用 text/math Block，与现有知识模板的 KaTeX 渲染方式兼容，不接收模型输出的 HTML。

## 提示词的重点

- 要求「题干具体线索 + 方法 + 本题成立的原因」，避免返回“综合运用”“灵活求解”等通用话。
- 方法选定后，补学生容易卡住的运算，不把基础代数拆成大量步骤。简单题不强凑三个突破点。
- 一条主解法覆盖各分问；最终答案独立保存。必要时简述另一种技巧，不同时铺开多套完整计算。
- 先解题、核对，再整理教学输出；不要求模型输出内部思维过程。
- 参考答案、OCR 和已有考点标签都当作待核对材料，不能覆盖原题明确条件，也不能成为新指令。
- 缺题面条件返回 `needs_input`；题面完整但推导不可靠返回 `needs_review`，二者分开。`draft` 只是生成稿，不等于已审定正确。

## 题目输入与模型能力

数学教辅题通常以 `img` 为主要题干，`stem` 可能为空；现有 `/api/kg/explain` 只支持非空文本大题，不能仅换一段提示词就覆盖所有数学题。

文本清楚时，将规范化题干及所有分问送入模型；图片题需要后端提供原题裁图或可靠识别文本。若当前配置模型已确认支持视觉，可走同一网关和模型的多模态调用；不支持时先做题目识别，不静默换成别的供应商或模型。只有关键符号确实无法确认时才要求补充，不能让学习者逐题重复确认清晰题面。

网关未明确支持 JSON Schema 时，把 Schema 随 user 消息提供并在后端验证；支持结构化输出的模型可额外使用相应模式，但仍保留服务端校验。user 消息同时重申“数学分层解析、只返回指定 JSON”，降低部分网关丢失 system 消息时的偏离。

## 验收与缓存

1. JSON 解析及 Schema 校验：拒绝围栏、缺字段、额外字段、错误状态组合和超长结果。
2. 业务校验：步骤与突破点 ID 唯一、有序；step_ids 均存在；draft 中必要字段非空；所有 tex 可严格排版，同时检测双重转义的公式命令。只调用 KaTeX 而不报错不代表它显示了原本想要的命令。本版不自动反复修复模型输出；结构错误或超时进入错误状态，允许用户重试。
3. 数学核对：模型提供可检查的证据；能够符号代入或数值核对的题再做工具校验。结构合格不能冒充数学已验证，模型自述“正确”也不作为工具验证结果。
4. 服务端保存原题内容哈希、提示词版本、Schema 版本、配置模型、返回模型（若有）、生成时间和复核状态。缓存区分题干/题图变化、模型与提示词版本；旧版 `answer/solution` 字符串不直接当作新版结构化解析。
5. 首次生成需登录、同一缓存键合并并发请求，生成任务按项目并发配置控制。结果保存服务端供多端读取；阅读展开与当前提示层级仅是临时界面状态，练习评分继续走既有账号同步。

## 当前例题的验收点

路径无关应导出 `f''-5f'+6f=xe^{2x}`；两个突破点是偏导相等与指数换元／共振处理，不能只重复题目所属章节。
`Q=(f'-5f)cos y` 的负号、取 `y=0` 而非随意除以 cos y、换元后初值、降阶后的积分常数都应讲清楚。
最终结果应等价于 `2e^{3x}-(x²/2+x+2)e^{2x}`，并给出初值与方程的代回证据。

## 首轮试跑暴露的问题

项目配置模型为 `deepseek-flash`，网关返回模型名为 `deepseek-v4.1-flash`。首轮直接生成分层 JSON，Schema 和引用检查通过，但模型把正确的 `f''-5f'+6f=xe^{2x}` 移项成了错误方程，随后只验证了自己推错的方程；摘要、特征根与具体推导还互相矛盾。
该结果应被拒绝，不能因为 JSON 合格或模型写了“验算成立”而上线。此发现是采用“先解题核对、再组织教学”及增加原题代回检查的依据；更换布局提示词本身不能保证数学正确。

## 两阶段复测结果

本题两阶段均请求项目配置的 `deepseek-flash`。先行解题选择了共振待定系数法，教学阶段据此输出 2 个突破点、5 个步骤及独立答案块。Schema、步骤引用和全部 24 个公式块的严格 KaTeX 校验通过。

将模型输出的最终函数解析后用 SymPy 独立计算，原始条件对应方程残差为 0，f(0)=0，f′(0)=1，且与已核对的正确函数恒等。首轮错误稿则被同样的原方程检查识别为不成立，尽管两个初值均满足。

这只是当前示例的回归结果，不能据此给其他题型自动加上“数学已验证”状态。题图作为权威输入已接入两阶段多模态调用，任务服务端持久化；其他题型的独立数学工具核对仍需逐类扩展。

逐段阅读还发现教学稿有一句“初值方程右端减 1”的措辞与它自己给出的正确等式不符；校对稿已改为明确的 `2C₁+3C₂−1=1 → 2C₁+3C₂=2`，原始模型稿保留。由此，最终函数的工具验算与整篇教学文本的复核应分别记录，不能把前者冒充后者。

## 正式接口、页面与信任边界

- 题目页入口：数学练习卡中的「逐题解析 · 突破点与细节」，也可单独打开 `/review-priority/explain/:itemId`。
- `GET /api/math/explanations?item_id=...` 读取当前题图、模型与提示词版本对应的服务端状态；已保存结果可匿名读取。
- `POST /api/math/explanations` 只接受 `{ "item_id": "...", "regenerate": false }`（regenerate 可省略），首次生成与重试需登录，按账号/IP 限流。拒绝浏览器提供的 URL、文件路径、题干、模型名及额外字段。
- 服务端从李林／张宇索引匹配 ID，仅允许静态 `math/img` 内的有限大小图片；规范化路径后再次验证目录边界，包括符号链接。破损 OCR 不作为生成依据。两个模型阶段均带原题图，避免先行稿反过来覆盖原题。
- 迁移 004 新增共享任务表；缓存键包含题图内容与元数据、提示词／协议／校对种子版本、配置模型及网关。任务阶段、结果、生成模型、复核状态保存在 PostgreSQL，其他设备直接读取同一份结果。
- 全局调度锁控制按配置并发认领，网络调用不持事务锁；任务每 15 秒续租，进程中断后可恢复，旧尝试不能覆盖新尝试。维护期间暂停认领。
- 更新恢复演练必须设置 `EW_BACKGROUND_TASKS=0`，防止复制的待处理任务在预检库中再次调用付费模型。主机更新服务需同步这一设置。
- 模型长内容只允许 text/math 两种块。Rust 用拒绝额外字段的类型和业务校验限制长度、状态、步骤引用；前端严格检查公式后以 React 文本和 trust=false 的 KaTeX 渲染。模型输出不作为 HTML、URL 或可执行指令。
- 当前示例的已校对解析绑定题图哈希和实际生成模型；其他题目的新结果均标记为模型生成稿，不继承示例的数学核对状态。

## 本地验证

前端全量单元测试与构建；后端包含队列去重、租约恢复、路径穿越／符号链接边界、两阶段 HTTP 传输、配置模型复用和模型自检不升级为人工校对的测试。隔离数据库 HTTP 验证匿名生成被拒绝、额外模型参数被拒绝、未知与非法题号被拒绝。更新器增加后台任务关闭的预检回归测试。

未校对的模型稿可由登录用户主动重生成，服务端仍按题目、账号与 IP 限流并设置 15 秒冷却；已校对种子不允许被这个入口覆盖。公式排版失败时页面隐藏该结果并提供重生成入口，不会一直重读坏缓存。
