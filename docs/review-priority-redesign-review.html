00一页结论

三个问题按严重程度排序。它们不是三个 bug，而是同一个原因的三次外化：页面把「分析过程」摆在了「分析结论」前面。

问题 1 · 结构

首屏是配置台

学科 → 题型 → 统计口径 → 分科 → 排序，五段控件向下堆叠约 700px，加上顶部导航，1440×900 屏幕上第一条排行正好落在折线外。用户进来先做 4 次选择，才换来一个结论。

问题 2 · 表达

「性价比」没有数字

priority 公式算得很细（四因子加权），但 UI 只给名次。行内并列「考过几年 / 近五年几回 / 成本中等」三套口径，除法留给用户做。名次不可解释，就不可信任。

问题 3 · 路径

页面止于「看」

点击排行行 = 选中，不是开始。从「看到第一名」到「做第一题」需要 2 次滚动 + 2 次点击。没有队列、没有计划、没有「下次从这继续」。

总体判断

这个页面已经拥有全部原材料：真题分值、年份分布、掌握缺口、成本估计、可练题目。它缺的不是数据，是把这些数据压缩成一句结论、再变成一个动作的能力。所以 redesign 的重点不是加法，而是排序——把结论提到最上面，把配置收进一条工具条，把「看」和「做」缝在一起。

先说做对的部分（这些不要动）
  • 全参数化 URL（subject / book / kind / order / kp）—— 可分享、可回退、可被导航记忆复用，这是本次改造能低成本落地的基础。
  • 分题型独立归一化：用「当年该题型总分」做分母，避免 2009 与 2024 的分值口径混算，比大多数同类工具严谨。
  • 408 不凑满分：规则草稿、回忆版、分值异常卷直接不进榜，近五年分母按实际有效年份显示。宁可显示 4/5 也不假装 5/5。
  • 推荐不跨题型、错题不提前重复，且「导入量 ≠ 无遗漏」写在文档里——这些克制决定了后面所有设计建议都只是「重排」，而不是「重做」。

02四维问题

每条问题都标了代码位置，方便直接对照。判断标准只有一个：它是否让用户更快地做出「先补哪个」的决定。

A · 信息结构

A1

四层筛选吞掉整个首屏，决策内容被推到第二屏

学科（2 卡）、题型（3 段）、分科（3–4 卡）、排序（3 段）共 11 个可点控件，全部排在榜单之前。其中「学科」与「分科」是包含关系，却用了同一种大卡片语言，视觉上像两个平级选项。

用户影响用户以为自己在「配置一个查询」，而不是「得到一份建议」。首屏没有任何信息告诉他值不值得往下滚。
A2

切换学科会静默重置题型与分科，用户失去位置感

L109-127 choose() 里切换 subject 会 delete book / delete kp，408 下填空还被强制改成大题。参数化的好处是 URL 可分享，坏处是状态变化没有任何可见反馈。

用户影响点了「408」之后发现题型从填空变回大题、分科从概率变回数据结构，却不知道该不该改回去。
A3

「统计口径」黄条插在题型与分科之间，阻断主流程

L175-177 一段 40 余字的方法说明，被放在用户还没看到任何结论的位置，并且常驻不可折叠。它其实属于「可信度」，应该跟页面底部已有的口径 details 合并。

用户影响在最需要顺畅下滚的位置遇到一段需要阅读的说明，形成一次被迫停顿。
A4

双栏配比失衡：左 1 个列表 vs 右 4 个模块

L201 lg:grid-cols-[0.9fr_1.3fr]，右栏塞了结论、指标、训练池（含两源分组）、真题依据四段。列表是壳，详情是肉，但视觉上两者在抢注意力。

用户影响视线在「扫列表」和「读长详情」之间反复横跳，滚动位置不断丢失。
A5

折叠规则桌面/移动不一致，且「查看全部」按钮的出现条件也是隐式的

L204 !expanded && index >= 4 && "hidden lg:flex"：桌面显示 8 条，移动端只显示 4 条；L213 的展开按钮在 ranked.length ≤ 8 时仅移动端出现。同一 URL 在不同设备的信息量不同。

用户影响手机用户以为题库只有 4 个考点，桌面用户以为「8 条就是全部」。

B · 核心信息传达

B1

页面叫「性价比」，但没有任何一个可读的性价比数值

行内是 "12/18 年 · 近五年 4/5 · 补齐成本中等" 三段并列，再加一条 17 段细条。三套口径、零个结论数。用户要自己把「年数 × 占比 ÷ 成本」在脑子里做除法。

用户影响扫十行也得不到「哪个最划算」——而这正是页面标题承诺的东西。
B2

排序依据存在但完全不可见，名次无法被解释也无法被反驳

math1Analysis.ts L128-129 里 priority = 分值占比 × 缺口 × 弱项 1.15 × 到期 1.08 ÷ 成本。这套逻辑相当讲究，但 UI 只透出「1、2、3」。凡是不能解释的排名，用户默认当成黑盒。

用户影响看到「无穷级数」排在第三会怀疑「它不就考过几次吗」，然后不再相信榜单，退回自己翻真题。
B3

真正的价值指标（分值占比）算了但从不展示

pointShare / recentPointShare 已经算好并用于排序，UI 里却只出现「年数」。于是用户以为排序靠考频，实际靠分值加权——两种心智模型对不上，名次自然显得随机。

用户影响用「考过几次」去验证一个按「占多少分」排的榜，验证必然失败。
B4

「补齐成本」既无量纲也无耗时，且实际含义与直觉相反

L124 cost = Math.max(…questions.map(q => q.cost))：取该考点下最难那道题的成本，而文案只说「补齐成本：中等（人工相对估计）」。项目文档里其实写清了「成本不是观测时长或提分预测」，但这层限定没有出现在界面上，用户仍会按「补这个点要多久」去理解。

用户影响预期管理失效——按「中等」投入时间，撞上最难的题就会觉得被坑。
B5

「无记录」被赋中性值 0.5，视觉上又与「已评估」无法区分

L127 const gap = confidence === null ? .5 : … 让未评估考点排进中段；而「待诊断」只是一个灰底小胶囊，和「巩固提升」的灰黄胶囊在低饱和下几乎同色。未评估 ≠ 已及格。

用户影响新用户看到满屏灰胶囊，会把「没测过」误读成「还行，不用管」。
B6

状态只给结论不给证据

「优先补弱 / 巩固提升 / 保持熟练」四色胶囊背后可能是 1 道题，也可能是 12 道题，胶囊不告诉用户。没有样本量的判断，等于没有判断。

用户影响做完一道题发现整页排名大洗牌，会觉得系统在乱猜；反之刷了十道仍显示「巩固」也会困惑。

C · 用户决策路径

C1

真实任务需要 6 步，每一步都要重新判断

选学科 → 选题型 → 选分科 → 选排序 → 点考点 → 读建议 → 找题。六步里没有一步给出「已完成」的信号，用户始终不确定自己是不是走对了。

用户影响「今晚 2 小时练什么」这个 30 秒该解决的问题，被拉成一次 2–3 分钟的探索。
C2

没有主 CTA：点击排行行 = 选中，不是开始

L203 onClick={() => choose("kp", …)} 只换右侧详情。想做题要滚到训练池、再点某一张题卡（openPractice）。从「看到第一名」到「开始第一题」= 2 次滚动 + 2 次点击。

用户影响页面最高意图的位置（第一名）反而是最不能行动的位置，转化在最后一米流失。
C3

排序切换与信息呈现脱钩

切到「近五年」时，行内主信息一字不变，最相关的「近五年 4/5」仍是 11px 灰字。用户切了排序，视觉上没有获得任何奖励，很快就不再切了。

用户影响三种排序退化成三种「稍微不一样的长相」，比较行为消失。
C4

只读报表：没有队列、没有计划、没有「继续」

URL 参数记住了位置（这点做得对），但界面上没有任何「上次看到哪 / 该继续做什么」的显式入口；也没有「加入今日计划 / 稍后」。

用户影响每天重新探索一遍同一个页面，无法把一次性浏览沉淀成学习任务。
C5

训练池用运营口径说话

L249 已导入 1523 题 · 大题 210 题 · 同考点 12 题 · 当前可练 3 题（含补基础） —— 这是数据完整性报表，不是学生语言。学生只关心：做哪道、多久、练完能怎样。

用户影响四个数字里只有一个对决策有用，另外三个增加认知负担，还暗示「题库很大但你不能练」。
C6

最需要引导的时刻（空态）只有一行灰字

L198 全部 unknown 时给一句「该分科还没有掌握记录…」。没有按钮、没有诊断入口、没有预期时长。而新用户和刚切到 408 的用户正好落在这里。

用户影响冷启动用户在这个页面拿不到任何结论，只能退出去——恰好是留存最脆弱的一批人。

D · 视觉呈现

D1

12 个同质白卡 + 1px 边框，靠线条分隔而非层级

英雄区、学科、题型、口径、分科、排行榜、详情四段……全部 rounded-xl border bg-card。结果是平铺表格感：没有任何一块在说「先看我」。

用户影响视线没有落点，平均分配注意力，等于没有优先级。
D2

最能表达「趋势」的年份条形，实际是装饰

17 段 × 6px 高，三档颜色（primary / primary 40% / muted），年份只能靠 title 提示——移动端不可 hover，条形信息归零。它本该是一眼看出「这个点是持续考还是偶尔考」的唯一图表。

用户影响用户看见一条花条纹，读不出任何结论，但它占掉了每行最贵的一行高度。
D3

三级数字同级，没有「主数字—辅数字」关系

Hero 统计 20px、详情指标 14px 粗、榜单行 12px，三处表达的都是「数量/占比」，却按容器分配字号而非按重要性。用户的视线无法通过字号找到答案。

用户影响每个数字看起来一样重要，于是每个都不重要。
D4

语义色过载：一屏四套颜色在说四件事

主色（选中/前 3/链接/CTA）、warning 黄（口径/补基础）、danger 红（弱项/到期）、success 绿（熟练），再加学科渐变色块。用户需要现场学习一张色表才能读懂状态。

用户影响颜色不再传达紧急度，只传达「这里有很多不同状态」。
D5

字号碎片化：8 个级别，10–11px 出现十余次

text-[10px] / [11px] / xs / sm / base / lg / 2xl / 3xl。正文与注释的差距被压到 1px，层级靠颜色区分，而颜色又已经过载（见 D4）。

用户影响小字区域（年份、成本、来源）整体被跳过，而这些恰是决策依据。
D6

移动端「短列表 + 长详情」的折返结构

列表折叠到 4 条（L204），详情要滚两三屏；切换考点后 L124 scrollIntoView 直接跳详情，用户想换一个考点必须先滚回顶部。

用户影响手机上是「进去—读完—退出—再进去」的循环，比较行为被结构性阻断。

03目标结构：结论在前，配置在后

原则：一屏之内必须完成「看见结论 → 知道为什么 → 开始做」这条链路。筛选一条不少，但压进一行工具条；详情不再常驻，改为下钻。

04关键模块规格

六个模块，其中 1–3 是本次 redesign 的真正增量（把「性价比」变成一个看得见的东西），4–6 是既有内容的重新编排。

模块 1 · ROI 数值：把 priority 从后端搬到台前

后端已经有完整公式，不需要改算法，只需要把中间量暴露出来并做一次归一化显示：

// 现有（math1Analysis.ts L128），保留不动 priority = (0.4·长期分值占比 + 0.6·近五年占比) · 缺口 · 弱项×1.15 · 到期×1.08 ÷ (1 + 0.35·(cost−1)) // 新增：同科目同题型内归一化到 0–100，作为「性价比分」 roi = round( priority / max(priority in group) × 100 ) // 拆解文案（hover / Drawer 内展示），让名次可解释 ROI 82 = 占分 6.2%（近五年加权） × 缺口 65% ÷ 成本 1.2
  • 显示双编码：数字（82）+ 一条横向比例条。纯数字显得假精确，纯色条无法比较，两者叠加才既可信又可比。
  • 保留「高/中/低」兜底：当组内样本 < 3 或全部 unknown 时，只显示「高 / 中 / 低」，不显示分数。避免冷启动阶段的数字噪音。
  • 口径可追溯：点击分数弹出因子拆解（占分、缺口、成本、弱项/到期加成），每个因子旁标注来源（真题 / 学习记录 / 人工估计）。

为什么值得做：这是全页唯一能兑现标题承诺的东西。没有它，「性价比」只是一个形容词；有了它，它才是一个可比较、可验证、可传播的指标。

模块 2 · 价值对比：用一张象限图说清「为什么不先学那个」

对应「价格对比」的位置。表格能排序但不能表达分布，而「性价比」本质是一个二维判断：值多少（占分）对要花多少（成本）。所以默认给一张 2×2 象限图，气泡大小 = 掌握缺口。

气泡面积 = 掌握缺口；数字 = 性价比分。点击气泡进入该考点的 Drawer。

  • 与表格并存，不做替代：象限图回答「整体该往哪使劲」，表格回答「第 4 名是谁」。用分段控件切换「图 / 表」，默认图。
  • 左上象限是唯一重点：给该象限一条底色，并在标题写「优先做」。其余三块用中性色，避免用户同时思考四件事。
  • 移动端降级：小屏不放图，改为「高性价比 Top5」纵向列表，避免 300px 高的图吃掉整屏。
  • 对比模式（P2）：表格行支持勾选 2–3 个考点，底部浮出对比条：占分 6.2/5.4/4.8、成本 中/低/高、缺口 65/48/—、预计提分 +4.1/+3.2/+2.6。

模块 3 · 价值说明：每个考点一句「为什么是现在」

现在是四句模板文案（「学习记录显示这里需要补弱，建议从基础方法开始…」），说的是方法而不是收益。改成一句可计算、带数字的结论：

「多元函数微分学」近 5 年考了 4 次，平均占当年大题 6.2 分。你最近 3 道同考点题（2 错 1 模糊）显示掌握度约 35%；补齐预计 35 分钟，按现有分差估算可拿回 4.1 分。
→ 值得今晚第一个做。

  • 结构固定为四段：考频 → 占分 → 我的证据 → 投入/回报。前两段来自真题数据，第三段来自学习记录，第四段是唯一的主观点，必须标「估算」。
  • 「预计提分」是全页最该被看见的数字，建议作为 Top3 行动卡的主数字（现在页面完全没有这个概念）。
  • 证据要可点：「2 错 1 模糊」后面挂一个链接，直接跳到那 3 道题的记录，让用户能核对。

模块 4 · 筛选与排序：从四层表单到一行工具条

  • 结构：学科胶囊 ｜ 题型分段 ｜ 分科胶囊 ｜ 排序 ｜ ⓘ。分组之间用 1px 竖线，不用卡片包裹；整条 sticky 吸顶（56px 高），滚动时始终可切。
  • 联动反馈：切换学科导致题型/分科被重置时，给一次 200ms 的高亮闪烁 + 一句 toast「已切到 408 · 大题 · 数据结构」。静默重置是当前最隐蔽的挫败点。
  • 排序与列联动（重点）：
    • 个人优先 → 主列为「性价比」，主数字 = ROI；
    • 历年考频 → 主列换成「考查次数」，行内把「12/18 年」放大为第一视觉，ROI 条淡化；
    • 近五年 → 主列换成「近五年占比」，并高亮年份条的后 5 段。
    排序变化要有 150ms 的位置过渡，让用户「看见名次真的动了」。
  • 新增两个轻量开关：「隐藏已掌握」（过滤 stable 且未到期）与「只看未诊断」（跳进空态诊断流）。两者都不改变数据，只改变视野。
  • 搜索框：数学大题 17 类、408 更多，超过 12 项时应有考点名搜索。
  • 口径 ⓘ：把黄条内容 + 底部 details 合成一个未读时带小圆点的弹层，首次访问自动展开一次。

模块 5 · 训练队列：把「题池」改成「今晚的任务」

现状是按来源分两组，每组顶部四行运营统计，下面是题卡。改成单列队列：

  • 每行一件事：题号 + 类型标签 + 预计时长 + 一个 ▶。来源（李林/张宇/王道）与匹配方式（同考点/方法/补基础）降为 10px 次级标签。
  • 队列顶部一个主按钮：「连续做 3 题 · 约 25 分钟」，进入串行作答，结束给小结（完成数 / 正确率 / ROI 变化）。当前每次只能做一题、做完回到页面，缺少「一段完整学习」的容器。
  • 运营数字移入 ⓘ：「已导入 1523 题 · 同考点 12 题」放进 tooltip，作为隐私性信息而非首屏语言。
  • 空队列要有出路：「当前没有可练新题」时给两个动作：去图谱看全部练习 / 直接做真题，而不是一句灰字。

模块 6 · 真题依据：年份点阵从装饰变成入口

  • 升级为 16×16 可点方格：实心 = 考过，色深 ∝ 该年该题型下的分值占比，浅灰 = 未作为主考点。点击直接打开原题（reviewQuestionHref 已支持）。
  • 推断趋势：在后 5 段下方加一条细底线或区间底色，标出「近五年」，让趋势读得出来，不依赖 hover。
  • 文字列表保留但收进折叠：默认折叠，只在用户点开某一格时才展开该年的题面与解析链接。

05内容层级与视觉规则

ReDesign 的另一半是减法：把 8 级字号、4 套语义色、12 个同质卡片收成一套有主张的体系。

L1 · 结论层

一句话 + 一个数

「先做 X，预计 +4.1 分 / 35 分钟」。字号 24–28px，全页只允许出现 1 次这个量级。每屏最多一个 L1。

L2 · 证据层

三因子 + 年份

占分、缺口、成本，13–14px，数字用等宽字体（tabular-nums）右对齐，保证列内可比。

L3 · 方法层

口径 / 来源 / 免责

11–12px，默认折叠在 ⓘ 与页脚 details。当前这些信息的位置是对的，只是不该在首屏插一段。

具体规则

  • 字号收敛到 5 级：28 / 20 / 14 / 13 / 11。删除全部 text-[10px]，最小 11px 且只用于标签。
  • 色彩收敛到 3 组：主色（结论与行动）、中性 3 阶（结构）、1 套语义（仅危险，用于「到期 / 明显薄弱」）。把 success 绿与 warning 黄从状态胶囊上撤下，状态改用「文字 + 图标形状」编码，颜色只保留一档强度。
  • 卡片减半：从 12 个降到 5 个容器（工具条、结论条、行动区、榜单、Drawer）。同层级内容不再各自包卡，用间距和字重分层。
  • 榜单改为表格语义：行高 56px，数字列右对齐，表头 11px 小写字母间距。表格比卡片列表更省纵向空间，也天然支持「排序 → 列变化」。
  • 状态双编码：● 红点 = 需要动手；○ 空心 = 数据不足；✓ = 已稳定。同时保留文字，色盲可用。
  • 暗色不做额外适配：沿用项目已有 token，不新增颜色变量，避免与 AppLayout 的 NookPhone 色块冲突。

07怎么验证：四个数字就够了

这个页面只有一个成功标准：用户更快地开始学。所有指标都应指向这一点，而不是停留时长。

主指标
页面 UV → 开始答第一题<15% → >35%
进入 → 首题开始（中位耗时）→ <45s
榜单行下钻率→ >60%
排序切换率→ >25%

基线需先埋点取一周数据；上表右列为目标值，不是当前值。

需要埋的事件
  • review_toolbar_change：学科/题型/分科/排序，带 from→to
  • review_rank_click：位置（名次）+ 交互类型（下钻 / 直接开练）
  • review_action_card_start：来自 Top3 卡的比例
  • review_roi_explain_open：因子拆解打开率（信任指标）
  • review_empty_state_action：空态下的选择分布

风险与「不做」清单

  • 警惕 ROI 的假精确。82 分必须有可展开的因子来源，否则它只是一个更精致的黑盒。组内样本 < 3 时降级为高/中/低。
  • 不要加第五层筛选（章节 / 难度）。这个页面的病是「太像配置台」，不是「选项不够」。
  • 不要给 unknown 赋 0.3 之类的低分。那会系统性抬高已有数据的弱项，让新用户永远看不到高价值考点。中性 0.5 + 显式标注「未评估」是更诚实的做法。
  • 收敛色彩不等于删掉警示。「补基础」「口径」的黄仍需保留，但要退出状态胶囊系统，只作为标签使用。
  • 象限图不做成唯一入口。移动端和「我就是要找第 7 名」的场景必须有表格。
  • 排序切换不要自动跳转详情。用户在看分布，不在挑单个。
