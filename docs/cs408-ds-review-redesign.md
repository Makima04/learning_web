# 数据结构大题复习性价比重设计

设计日期：2026-11-09。范围为「复习性价比 → 408 → 数据结构 → 大题」。任务分类仍为产品与数据设计；王道原书位置标注已在本地页面实现，未部署。

## 1. 设计目标与已确认的问题

复习入口先回答「练算法设计，还是练应用分析」，再回答「具体练哪类、哪种方法、哪些题」。

本地现状核对：

- `frontend/public/cs408/wangdao2027/ds.json` 有 164 道大题，均没有 `facets` 细标签。
- 其中只有 1 道挂在 `ds.algo.design` 下，题目是分析程序段的时间复杂度。大量真正的算法设计题散落在线性表、树、图、查找、排序章节。
- 真题的算法设计有时以 `ds.algo.design` 为主考点，有时以链表、图存储、拓扑排序等为主考点。当前按主考点相等匹配，会漏掉相关王道题。
- 当前合格统计集内有 12 个年份、24 道数据结构大题。原始年份题号存在变化，例如 2016 年数据记录中的数据结构大题为第 42、43 题，因此不能用固定题号区分算法题和应用题。

结论：需要单独建立「考试任务分类」，并与知识图谱、方法标签建立关联。

### 算法设计：按操作对象分组，组内按方法训练

| 类别 | 方法与典型任务 | 作答检查 |
| --- | --- | --- |
| 数组与顺序表 | 原地删除与去重、逆置与循环移位、多指针归并与交集、计数标记、主元素、区间或后缀信息维护 | 不变量、边界、时间与辅助空间 |
| 链表 | 删除与释放、逆置、拆分与合并、快慢/间距指针、公共后缀、重排与判环 | 头结点约定、断链与接链顺序、空表与单结点 |
| 栈、队列与串 | 栈队列基本操作、双栈模拟队列、括号匹配、对称性判断、串操作 | 判空判满、操作次序、辅助空间 |
| 树与二叉树 | 递归统计、非递归遍历、层次遍历、祖先路径、表达式输出、BST 剪枝与查找 | 递归含义、返回值/状态、空树、输出格式 |
| 图 | 邻接矩阵扫描、邻接表操作、DFS/BFS、路径与连通性、拓扑序列判定 | 存储约定、访问标记、非连通图、复杂度 |
| 查找与排序算法 | 折半与有序性利用、分区与第 k 小、堆与 Top-K、归并与排序改写 | 正确性、适用前提、平均/最坏复杂度 |

方法是可交叉的标签，不再与结构类别并列竞争。例如「链表重排」可同时涉及快慢指针、逆置、交替合并；「树上求高度」可能是递归，也可能是层次遍历，需要按题目要求核对。

不单独把「动态规划、贪心、递归」设为和链表、树、图并列的首页类别。只有题目实际使用且已核对的方法，才加入方法覆盖。

### 应用分析：按知识点及要求产出的结果训练

| 类别 | 下钻知识点 | 作答检查 |
| --- | --- | --- |
| 算法分析与结构比较 | 时间/空间复杂度、逻辑结构与存储结构、操作效率 | 执行次数、量级、比较前提 |
| 线性表、栈、队列与串 | 存储与操作、出入栈序列、循环队列状态、表达式、KMP | 状态推演、下标与判定依据 |
| 树、二叉树与编码 | 结点数与高度、遍历与重建、树/森林转换、哈夫曼树、WPL、前缀编码 | 结构图、计算过程、性质或反例 |
| 图的存储、遍历与应用 | 矩阵/表转换、DFS/BFS、MST、最短路径、拓扑排序、关键路径 | 每一步选取、更新状态、结论条件 |
| 查找结构与查找效率 | 折半判定树、BST/AVL、B/B+ 树、散列、成功/失败 ASL | 构造过程、冲突处理、比较/探测口径 |
| 内部排序与外部排序 | 每趟结果、算法识别、稳定性与复杂度、堆调整、多路归并、败者树、置换选择、最佳归并树 | 中间状态、归并趟数、I/O 或 WPL 的计算前提 |

同一知识点可出现在两条路线。例如「拓扑排序」在算法路线练编码与唯一性判定，在应用路线练手推序列与工程分析。两者的任务级掌握分别显示，共享基础知识链接。

## 3. 页面与交互

筛选顺序为「408 → 数据结构 → 大题 → 算法设计 / 应用分析」。路线切换使用醒目的两个页签，URL 持久化为 `task=algorithm|application`。

首页分为三层：

1. **路线概况**：有效真题样本、已检验方法或知识点数量、待复测数量。算法路线说明检查思想、实现、复杂度；应用路线说明检查原理、过程和结果。
2. **分类目录与优先顺序**：每行展示类别、历年/近期真题证据、方法或知识点覆盖、可练王道题数、掌握证据、补齐成本。只在同一路线、相同分类层级内比较优先级。
3. **下钻训练区**：先显示该类型的知识与解题路线，再显示方法/知识点清单、代表题、补练、延迟复测，以及完整题库和真题依据。

点击「链表」后，看到的是「删除 / 逆置 / 双指针 / 合并与重排……」的覆盖情况。点击「散列」后，看到的是「建表与冲突 / 成功 ASL / 失败 ASL / 删除……」。每项展示收录题数和可练题数，明确区分题库总量与本次推荐量。

每次默认推荐少量代表题；完整题库始终可展开。切换路线、类别或方法后清空旧作答队列，避免加载中的旧题覆盖新筛选。真题、知识复习、题集和答案往返保留任务及分类上下文。

没有练习证据时显示「待诊断」，先用代表题检验。目录不因个人筛选后暂无新题而消失；缺题、待审核与已练完分别提示。

### 王道题目的原书位置（已实现）

所有王道题目明确展示科目、章号、小节号、小节名称及该小节内的题型题号。例如：

> 王道 · 操作系统 · 第 2 章 · 第 2.3 节 · 同步与互斥 · 大题第 1 题

训练列表、宽屏作答台、窄屏作答卡、王道题集、知识复习引用及错题复习入口采用同一位置格式。长出处允许换行，避免原书题号被截断。保留做题本页码、原书答案页与真题年份；本次队列的 `1/3` 与原书题号分别显示。

位置取自现有题库的 `book`、`section`、`section_name`、`kind`、`qno`，不能使用推荐列表序号替代原书题号。题型区分大题与选择题，防止同小节编号相同的题混淆。缺失章节信息明确标为待核对。

## 4. 分类与题库数据

保留现有 `kind=big`、原题 ID、知识图谱 `kp_ids` 和出处。新增独立的任务标注，避免通过改写原考点 ID 强行匹配。

建议的数据字段：

```ts
interface DsReviewAnnotation {
  itemId: string;
  canonicalQuestionId?: string; // 经核对的同一道原题，王道收录真题时用于证据去重
  status: "reviewed" | "draft";
  tasks: {
    task: "algorithm" | "application";
    primaryGroupId: string;    // 该任务唯一的主分类，作为统计归属
    kpIds: string[];           // 与现有知识图谱的关联
    techniqueIds: string[];    // 明确核对的方法/知识技能
    primaryTechniqueId?: string;
    subquestions?: string[];   // 混合任务题对应的小问
    points?: number;           // 仅在已核准小问分值时填写
  }[];
  note: string;                // 分类依据、特殊约定或待审核问题
}
```

- 真题与王道采用同一份分类目录，标注文件作为源数据进入版本管理，再由脚本生成前端索引；不手改生成的 JSON。
- 对现有 164 道王道大题逐题审核。章节和关键字可生成草稿，不能把整章自动判为一种任务。第 5.3 节同时存在性质分析和大量遍历算法，正是需要逐题区分的例子。
- 只要求思想、无需代码的题，也可能是算法设计；要求分析已有代码复杂度的题归应用分析。依据解答任务判断，不能仅检测「算法」或「设计」字样。
- 混合题可有两种任务，但只能按核准的小问分值拆分统计。无法拆分时显示关联练习，单列待审核分值，不能把整题分值重复算给两条路线。
- 保留现有真题质量范围和排除原因。分类扩展不意味着把来源质量不足的卷加入性价比统计。
- 索引与题干分片携带一致标注，缓存版本同步更新，保证计数、排队和打开原题的一致性。

## 5. 统计、性价比与掌握证据

**考频**：只统计有效真题，按年份和主分类去重。同一题的多标签只提供关联，不增加主考次数；王道题数只代表训练资源。

**分值**：首页展示有效年份中该类别真实平均分值，即「类别分值之和 / 有效年份数」，以及具体年份与题号。任务内占比的分母固定为当年整条任务路线的有效分值，不能随方法筛选变化。未核准的混合题分值明确列出，不静默当零。

**优先级**：在同一路线内综合真题分值、近期证据、该任务的掌握缺口、相对补齐成本和到期复测状态。未知掌握保持中性；没有真题统计的类别不产生伪精确的性价比分。类别层与方法层不放在一张排行榜相互竞争。

**训练匹配**：先同任务，再同方法或知识技能，随后补同类别代表题。先修题单独标明「补基础」，不能冒充该方法的覆盖证据。不同类别可通过方法关联，但必须明确相关性。

**掌握**：沿用代表题检验、薄弱补练、首轮通过后 3 天复测的流程。独立证据按原题去重，王道里的某年真题与真题卷里的同一道题不能充当两道不同代表题。算法中的编码表现不直接代替应用中的手推表现。

**旧进度**：保留账号中的原题评分、错题、收藏、作答记录，按新标注重新派生覆盖状态。旧知识点总掌握仅作基础参考，不能迁移为所有新任务或方法已掌握。若新增小问或能力维度评分，必须扩展服务端账号数据并接入同步队列与 `accountSync`，不得只存本地。

## 6. 具体落点与验收

实现顺序：任务分类目录与标注源数据 → 标注审核与生成脚本 → 按任务/分类聚合和匹配 → 两条路线页面 → 旧链接与进度兼容。

主要落点为 `reviewPriority` / `math1Analysis` 的聚合接口、`techniqueTraining` 的匹配条件、`ReviewPriorityPage` 的筛选与下钻、`paths` 的上下文传递，以及王道和真题生成管线。408 的分类应独立成模块，避免将大量数据结构专属规则塞入通用数学分析函数。

验收应覆盖：

- 有效统计集中的 24 道数据结构大题全部审核；164 道王道大题都有审核结论，缺失题面或存疑题明确待审核，不强行归类。
- 数组、链表、树、图等算法题都能进入对应训练，时间复杂度分析题进入应用分析；混合题按审核结果处理。
- 同知识点在两条任务路线的题目、覆盖和证据相互独立；原题 ID、原题内容和原有用户记录保持可追溯。
- 各主分类分值与原卷可核对，含混合题的已分配与待审核分值之和等于原始总分；多标签及王道收录真题不造成重复统计。
- 过滤只改变当前视图，不改变考频样本、统计分母或题库总量定义；无统计样本的目录仍可补练。
- 方法标签有明确显示名；缺少两道独立代表题时不声称完成覆盖。
- 刷新、前进后退、从题集或知识复习返回均保留路线和类别；手机布局下两条任务路线和训练入口可见。
- 登录状态下评分、错题、收藏与复测证据能够在另一设备拉回并得到一致结果。

任务分类、题库标注和统计聚合尚待实现；王道原书位置标注已在现有页面统一实现。
